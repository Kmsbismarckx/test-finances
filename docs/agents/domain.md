# Domain docs

## Layout

This repository uses a single context:

- GLOSSARY.md at the repository root: domain terminology.
- docs/adr/: architectural decisions.

## Before exploring

Read GLOSSARY.md and ADRs relevant to the work.

If these files do not exist, proceed silently. Do not suggest
creating them upfront. The domain-modeling skill creates them
when terms or decisions are resolved.

## Vocabulary

Use terms defined in GLOSSARY.md in issue titles, proposals,
hypotheses, tests, and code. Avoid synonyms the glossary rejects.

If a concept is missing, reconsider the terminology or note
the gap for domain-modeling.

## Decision conflicts

Explicitly flag any proposal that contradicts an existing ADR,
identify that ADR, and explain why the decision should be reopened.
