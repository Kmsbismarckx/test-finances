# Авторизация, SMS в РФ и восстановительные ключи

Проверено 7 ноября 2026 года. Исследование для [«Поставщики авторизации, SMS и ключей для российских номеров»](https://github.com/Kmsbismarckx/test-finances/issues/11). Это shortlist для совместного выбора, а не выбор поставщика или подтверждение подключения. Регистраций, оплат и отправок SMS не выполнялось. Гражданство, резидентство, форма деятельности, доступные карты и бюджет владельца неизвестны.

## Вывод для решения

Есть конкретные составные варианты: **Supabase Auth (managed или self-hosted) + российский SMS-шлюз + отдельная служба выдачи с Yandex KMS**; либо **Keycloak + SMS-интеграция + та же отдельная служба**. **Vault Transit** — альтернативный самостоятельно эксплуатируемый компонент защиты восстановительных копий. Ни один из них целиком не реализует согласованный протокол выдачи ключа устройству. Выполнимость следует из документированных интерфейсов ниже; интеграции и эксплуатационные гарантии ещё не проверены.

Основание и обязательные ограничения — [подтверждённое решение об архитектуре](https://github.com/Kmsbismarckx/test-finances/issues/9#issuecomment-6697155466) и [предыдущее исследование](https://github.com/Kmsbismarckx/test-finances/blob/b85c976/docs/research/security-sms-recovery.md). Обычный sync и поддержка не получают ключи; администратор службы выдачи остаётся доверенной стороной. SMS-вход сохраняет другие устройства, явное восстановление отзывает остальные сессии. После подтверждения отзыва каждый новый сетевой запрос должен отклоняться; офлайн-копии дистанционно не удаляются. Противоречий локальному ADR 0001 не обнаружено.

## Авторизация: три ограниченных варианта

| Вариант | Подтверждённые возможности | Подключение, расходы, ограничения |
| --- | --- | --- |
| Supabase Auth managed | Email/password и phone OTP документированы; Send SMS Hook заменяет встроенную доставку региональным шлюзом. Это основной SMS-вход, не обязательный MFA. [Пароли](https://supabase.com/docs/guides/auth/passwords), [phone login](https://supabase.com/docs/guides/auth/phone-login), [hook](https://supabase.com/docs/guides/auth/auth-hooks/send-sms-hook). | Free: $0, 50 тыс. MAU, два активных проекта, пауза после недели неактивности. Pro от $25/мес, 100 тыс. MAU, далее $0.00325/MAU; SMS оплачивается отдельно. [Тарифы](https://supabase.com/pricing). Send SMS доступен Free/Pro: [матрица hooks](https://supabase.com/docs/guides/auth/auth-hooks). |
| Supabase Auth self-hosted | Тот же подход с HTTP hook; официально описаны переменные окружения и проверка подписи webhook. Phone auth включить, auto-confirm выключить. [Конфигурация](https://supabase.com/docs/guides/self-hosting/self-hosted-auth-hooks). | Нет тарифа managed MAU, но инфраструктура, обновления, резервные копии и дежурство — на владельце. Хостинг и его оплата ещё не выбраны. Возможность самостоятельно развернуть не доказывает доступность любого хостера. |
| Keycloak self-hosted | OIDC, парольная аутентификация и расширение authentication SPI; SMS-only вход требует собственной интеграции/проверенного расширения, готовая поддержка российского шлюза официальными источниками здесь не установлена. [Проект и Apache-2.0](https://github.com/keycloak/keycloak), [SPI](https://www.keycloak.org/docs/latest/server_development/), [OIDC endpoints](https://www.keycloak.org/securing-apps/oidc-layers). | Лицензионная плата за Apache-2.0 не требуется; сервер, БД и эксплуатация оплачиваются отдельно. Больше работы по SMS-flow, связыванию идентификаторов и восстановлению, чем у готового Send SMS hook (оценка исследования). |

Managed Supabase принимает карты, выставляет USD; исключения для крупных авансов через поддержку. Перечень платёжных брендов **не подтверждает принятие карты конкретного банка/страны**. [Billing FAQ](https://supabase.com/docs/guides/platform/billing-faq) и [terms](https://supabase.com/terms) не дают достаточного основания объявить подключение для неизвестного плательщика доступным: запросить письменное подтверждение по стране/форме деятельности и платёжному инструменту. Нельзя выводить запрет только из русского номера конечного пользователя.

Supabase публикует на дату проверки defaults: 30 SMS/час на проект, 60 секунд между OTP одному пользователю; verify — 30 запросов/5 минут на IP; встроенная почта — только 2 письма/час, для production потребуется отдельная настройка. [Rate limits](https://supabase.com/docs/guides/auth/rate-limits). Это не готовая защита бюджета: отдельно определить лимиты номера, устройства, IP, учётной записи, суммарного расхода и неверных кодов, TTL/одноразовость, временные блокировки и уведомления.

**Обязательные доработки для любого auth-варианта (вывод из требований):** одна стабильная учётная запись с email и подтверждённым телефоном, без создания дубля при SMS-входе; пароль восстанавливается только через телефон; стандартный email password-reset не должен обходить это правило. Обычный SMS-вход и явное восстановление — разные действия. Изменение телефона требует свежего системного подтверждения на iOS; провайдер auth сам не доказывает такую проверку.

## SMS: РФ подтверждать по операторам и шаблону

| Кандидат | Доказательство РФ и API | Цена и условия на дату проверки |
| --- | --- | --- |
| SMS.RU | Официальные тарифы отдельно для МТС, МегаФона, Билайна, Т2; есть send/status/cost, callback и дневные лимиты. [API](https://sms.ru/docs/api), [предварительная стоимость](https://sms.ru/docs/api/api_group_sms/cost). | Общая таблица: SMS **от** 8.50/8.40/8.40/8.36 ₽ соответственно; имя 3000/2550/2080 ₽ в месяц, у Т2 бесплатность относится к рекламе, для шаблонов имя 2450 ₽/месяц. Шаблоны оплачиваются отдельно ежемесячно. Это нижние границы, не котировка нашего OTP. [Тарифы](https://sms.ru/price). |
| SMSЦентр (SMSC.RU) | Официальная страница перечисляет российские сети, включая четыре крупных оператора; HTTP API документирован. [Тарифы](https://smsc.ru/tariffs/), [HTTP API](https://smsc.ru/api/http/). | Таблица имени: МТС 3000, МегаФон 2550, Билайн 2080, Т2 2450 ₽/месяц; международные маршруты имеют отдельные ставки. Точная цена OTP зависит от маршрута, оператора, категории и пакета; единую достоверную цену за код не устанавливаем. |

SMS.RU заявляет оплату картой/СБП и безналичный расчёт для юрлиц/ИП; защитные лимиты номера/IP и суммарных кодов включены по умолчанию. [Официальная страница](https://sms.ru/). Доступный путь **коммерческой** отправки OTP для физлица/самозанятого/иностранной компании, документы, минимальный платёж, возможность общего имени, сроки согласования шаблона и точную цену надо подтвердить у каждого кандидата. Для SMSC договор/FAQ прямым чтением инструмента возвращали 404, хотя тариф/API индексируются: договорную доступность не считаем проверенной.

Это доказательство опубликованного предложения доставки **в российские сети**, не проведённый тест доставки. +7 включает также Казахстан: фильтр одного префикса недостаточен. До запуска потребуются согласование категории авторизационного шаблона и тесты МТС/МегаФон/Билайн/Т2, перенесённых номеров и нужных региональных операторов; измерить задержку, долю доставки, дубликаты и поведение повторной попытки. Тесты здесь не проводились. Обещание «много стран» не заменяет эту проверку. Код нельзя писать в URL/логи; API ключ шлюза хранится только на сервере. Доставка SMS и проверка одноразового кода — разные обязанности.

## Защита восстановительной копии: два компонента

| Компонент | Подтверждено | Цена, доступность и переносимость |
| --- | --- | --- |
| Yandex KMS, регион Россия | encrypt/decrypt/reEncrypt/generateDataKey; раздельные роли encrypter/decrypter, отдельный каталог рекомендован документацией. [IAM](https://yandex.cloud/ru/docs/kms/security/). Есть Control Plane и Data Plane аудит, включая decrypt. [Audit Trails](https://yandex.cloud/ru/docs/kms/at-ref). | Рублёвый пример симметричного тарифа: 0.00439 ₽/час за активную версию и 3.16 ₽/10 тыс. операций; одна версия за 720 часов ≈3.1608 ₽, плюс операции. После удаления версии тарифицируются ещё три дня. Это только KMS, не цена всей службы. [Тариф](https://yandex.cloud/ru/docs/kms/pricing). |
| Vault Transit self-hosted | API криптографических операций и ротации; данные приложения хранить вне Transit. [Transit](https://developer.hashicorp.com/vault/docs/secrets/transit). Audit device пишет запросы/ответы, большинство строк HMAC-хешируются, числовые поля не скрываются автоматически. [Audit](https://developer.hashicorp.com/vault/docs/audit). | Это не тариф managed KMS: отдельно серверы, backup, unseal, обновления и эксплуатация. Лицензия BSL с Additional Use Grant разрешает production при условиях, связанных с неконкурирующим использованием; не объявляем её безусловно свободной. [LICENSE](https://github.com/hashicorp/vault/blob/main/LICENSE). Доступность коммерческой поддержки/загрузок для неизвестной стороны не проверена. |

Yandex допускает физлиц и юрлиц, но требует платёжного аккаунта, проверка физлица может закончиться отказом, из части стран регистрация недоступна. Новые физлица начинают с платного потребления, не бесплатного trial. [Регистрация, обновлена 03.11.2026](https://yandex.cloud/ru/docs/billing/quickstart/). Оплата зависит от резидентства плательщика: РФ — RUB и карты российских банков; Казахстан — KZT и нероссийские карты; остальные — USD и нероссийские карты; есть СБП. [Оплата физлиц](https://yandex.cloud/ru/docs/billing/payment/payment-methods-individual). Для юрлица отдельно сверить договор и банковский перевод; гражданство пользователя не выводить из языка беседы.

Опубликованные квоты KMS: 100 симметричных ключей, до 100 версий ключа; encrypt максимум 32 КБ. [Лимиты](https://yandex.cloud/ru/docs/kms/concepts/limits). Из этого не следует схема «KMS-ключ на каждого пользователя»: вместимость, повышение квот и модель envelope encryption требуют отдельного проектирования. Приватный материал мастер-ключа не считать экспортируемым без документированного механизма. План выхода должен обеспечить переупаковку восстановительных копий через разрешённую службу до отключения старого KMS; иначе сохранённый ciphertext не гарантирует восстановимость. Для Vault также отдельно проверять exportability/backup и восстановление выбранной версии, а не обещать перенос ключа по факту наличия API.

## Что ещё должна делать отдельная служба выдачи

Следующее — архитектурные критерии из принятого решения, а не возможности, автоматически купленные вместе с KMS:

1. Проверять вход, принадлежность запроса учётной записи и активность конкретного устройства/сессии **при каждом запросе** выдачи и sync. Подпись действующего JWT сама по себе не подтверждает отсутствие отзыва. Supabase прямо предупреждает: access token живёт до exp после signOut; session_id можно сверять с auth.sessions. [Сессии](https://supabase.com/docs/guides/auth/sessions), [signOut scopes](https://supabase.com/docs/guides/auth/signout). Для восстановления предусмотрен scope others, но атомарность отзыва и выдачи ещё требует протокола.
2. Иметь авторитетное состояние отзыва, отказ при невозможности проверить его, согласованную границу подтверждения отзыва и отсутствие устаревшего разрешающего кеша. В Keycloak есть introspection endpoint для confidential clients, но его существование не доказывает нужную границу согласованности. [OIDC endpoints](https://www.keycloak.org/securing-apps/oidc-layers). Отозванное устройство не должно обходить проверку через другой endpoint, long-lived sync channel или прямой доступ к БД.
3. Отделить workload identity sync от выдачи: sync без decrypt/IAM-admin; служба выдачи с узкими правами на нужные ключи; поддержка без выдачи, аудитор без decrypt. Разделять права развёртывания, назначения IAM и просмотра логов. Администратор, способный изменить службу, остаётся доверенным. Облачная проверка IAM не знает бизнес-событие «отозвано устройство» автоматически.
4. Выдавать только необходимый клиентский ключ после входа по согласованному, проверенному протоколу; не экспортировать мастер-ключ и не передавать ключи фоновой задаче. KMS защищает копию, но не заменяет протокол доставки клиенту. Формат ciphertext, библиотеки, binding запроса к устройству, ротация и действия при компрометации ещё не выбраны; самодельная криптография не предлагается.
5. Настроить и проверить аудит **фактических decrypt и выдач**: субъект/устройство, результат, причина, идентификатор запроса; без OTP, токенов, ключей и финансового содержимого. Облачный decrypt audit дополнить журналом решения о выдаче; отдельно ограничить доступ к журналам и срок хранения.

## Переносимость и следующий совместный выбор

Стабильный внутренний идентификатор учётной записи не должен зависеть от SMS-оператора. SMS-адаптеру достаточно send/status/cost, но смена шлюза всё равно требует согласования имени/шаблона. Для auth заранее проверить экспорт пользователей, хешей паролей и телефонов; активные сессии считать отдельной миграцией. Keycloak export JSON явно **не включает** persisted sessions, revoked tokens и события и требует остановки узлов для согласованности. [Import/export](https://www.keycloak.org/server/importExport). Наличие self-hosted Supabase уменьшает зависимость от SaaS, но бесшовная миграция конкретного production-конфига здесь не доказана.

Для [«Выбор сервисов авторизации, SMS и управления ключами»](https://github.com/Kmsbismarckx/test-finances/issues/12) достаточно обсудить три композиции: managed Supabase + региональный SMS + KMS; self-hosted Supabase + региональный SMS + KMS; Keycloak + интеграция SMS + KMS/Vault. Они не ранжированы вместо пользователя.

Перед окончательным выбором нужны ответы:

- От владельца: страна/резидентство плательщика, физлицо/ИП/юрлицо, доступная оплата, бюджет фиксированный и на SMS, ожидаемые MAU/OTP и готовность обслуживать auth/Vault. Гражданство уточнять только если оно требуется условиями поставщика.
- От SMS-кандидатов: коммерческий OTP для указанного статуса, договор/верификация, конкретные РФ-операторы и регионы, цена нашего шаблона с НДС и всеми фиксированными платежами, лимиты throughput/баланса и порядок изменения маршрута. Число успешных входов не равно числу оплаченных сегментов SMS.
- От managed auth/облака: письменная доступность для реального плательщика и способа оплаты; регионы хранения телефона/email, условия выгрузки и удаления, SLA и нужные квоты. Правовые обязательства по персональным данным требуют отдельной проверки под фактического оператора приложения.
- Технический gate после выбора: прототип объединённого email+phone входа, запрет email-reset, явное восстановление с отзывом others, отказ **каждого** следующего sync/key запроса после отзыва, аудит без секретов, восстановление после потери устройств и процедура миграции escrow. Это будущая проверка, не выполненный тест.

Цены — снимок публичных страниц на указанную дату, не оферта для неизвестного клиента. Не установлены: договорная доступность SMSC, acceptance конкретных карт/сторон, фактическая доставка SMS, производительность выбранного развёртывания, полный месячный бюджет и безопасный клиентский протокол. Исследование достаточно для выбора направления и точных вопросов поставщикам; вопрос выбора остаётся открытым.
