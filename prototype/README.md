# THROWAWAY: Swift → Rust → SQLCipher

Вопрос: пригодна ли предварительная связка UniFFI, rusqlite/SQLCipher Community и будущая доставка XCFramework/Swift Package для локального MVP? [Вопрос карты](https://github.com/Kmsbismarckx/test-finances/issues/17).

Это технический прототип с настоящими Swift/Rust вызовами и scratch-базами, а не реализация приложения. Все записи вымышленные; ключ — **публичная константа 0x42 × 32**, которая намеренно не защищает реальные секреты. Авторизации, Keychain и серверного протокола здесь нет.

## Запуск

```bash
bash prototype/run.sh
```

Нужны Rust/Cargo, Swift compiler и Apple Command Line Tools; первоначальная загрузка Cargo-зависимостей требует интернета. Скрипт фиксирует зависимости через Cargo.lock, генерирует Swift bridge и module map, компилирует в Swift 6 mode, запускает сценарии отдельными процессами, сохраняет `prototype/results/observations.json` и самодостаточный `prototype/results/report.html`. HTML открывается двойным нажатием и воспроизводит реальные наблюдения, но сам не запускает Rust.

Базы создаются только в `prototype/output/PROTOTYPE-finance-*`; каждый запуск использует новый каталог. Никакие пользовательские файлы не удаляются. Сборки/сгенерированные bridge-файлы/scratch-базы исключены из Git. Ветка одноразовая, без PR/merge.

## Фактически проверено на macOS ARM64

- Swift 6.2.3 → UniFFI **0.32.0** → Rust **1.90.0** → rusqlite **0.40.2**, libsqlite3-sys **0.38.2**, SQLCipher **4.14.0 community**, provider **commoncrypto**. `cargo-platform` закреплён **0.3.1**: выбранный resolver-ом 0.3.3 требует Rust 1.91.
- Расход сохраняется, читается новым процессом, повтор той же команды не дублирует запись. Суммы — целые копейки в фикстуре, не универсальная модель всех валют.
- Перевод, очередь и квитанция результата — одна транзакция. Выход процесса без Drop до commit оставляет нулевое изменение, после commit сохраняет обе стороны и очередь. Это не испытание потери питания или дисковых ошибок.
- Явная отмена через `Control` до commit откатывает изменения; после commit возвращает сохранённый исход. Повтор команды по ID читает квитанцию и не дублирует перевод. Обычный Swift `Task.cancel()` в данном сценарии не остановил Rust-команду: нельзя заменять им предметный протокол отмены.
- Ручной `close()` во время приостановленной команды закрывает вход новых команд, вызывает откат и закрытие соединения, вызывает zeroize контролируемого ключевого Vec (после этого его длина нулевая). Это не наблюдение блокировки iPhone и не доказательство стирания всех копий ключа в Swift/FFI/SQLCipher.
- Миграция v1→v2 на копии сохраняет историю/очередь. Выход процесса без Drop до commit и после commit до активации позволяет открыть копию ожидаемой версии. SHA-256 исходного файла неизменен после всех попыток; повтор на новой копии успешен. Источник заранее закрыт в DELETE mode, без WAL: это не безопасное копирование активной WAL-базы.
- Данные с известным маркером действительно записаны и зафиксированы, затем изменены с маленьким cache для создания WAL/rollback-журнала. Основная база, реально созданные WAL, SHM и rollback-journal просканированы: открытого маркера нет. `temp_store=MEMORY` и `synchronous=FULL` проверены чтением фактических PRAGMA. Поиск маркера — ограниченная проверка утечки, не доказательство криптографической безопасности.
- Неправильный ключ отклонён без изменения исходного файла. Один JSON-пример сохраняет неизвестное вложенное поле и целое 9007199254740993 при изменении известного поля. Это не выбор протокола и не матрица совместимости реальных выпусков.

Полные результаты и окружение: `results/observations.json`; декларации лицензий/версий 104 Cargo-пакетов: `results/dependencies.json`. Наличие пакета в metadata включает зависимости других targets и не означает линковку каждого пакета в macOS-бинарник.

## Не проверено / окончательный выбор пока не сделан

Полный Xcode отсутствует: `xcodebuild` сообщает об active developer directory CommandLineTools, `simctl` недоступен. Поэтому не выполнены сборка для iOS, создание XCFramework и включение его в локальный Swift Package, simulator/device запуск, системный Keychain, Face ID и реальные lock/background события. Минимальная iOS **не определена** host-сборкой. Нужны полный Xcode с iOS SDK/runtime, затем физический iPhone для проверки системной защиты и lifecycle.

Также остаются активация мигрированной базы/журнал восстановления при замене рабочего файла, полный диск/I/O/power-loss, ограничение памяти на устройстве, все копии/экспорты/системные бэкапы, сеть и выдача/ротация ключей, матрица совместимости выпусков, Android/Windows cross-build. `close()` сериализован Mutex и в прототипе ждёт короткую локальную транзакцию; дедлайн закрытия и зависшие настоящие callbacks не испытаны.

Вопрос остаётся открытым до iOS-проверок и живого вердикта пользователя. ADR 0004 остаётся `proposed`. Хост-результат — положительное свидетельство для продолжения, не окончательное подтверждение всей связки.

## Первичные источники и лицензии

- [UniFFI](https://mozilla.github.io/uniffi-rs/latest/) — MPL-2.0; runtime/generator согласованы одной версией. Лицензия сгенерированного кода требует отдельной проверки перед распространением продукта.
- [rusqlite](https://github.com/rusqlite/rusqlite) и libsqlite3-sys — MIT; фактические флаги: `bundled-sqlcipher`, без vendored OpenSSL на этом host.
- [SQLCipher design](https://www.zetetic.net/sqlcipher/design/) и [API](https://www.zetetic.net/sqlcipher/sqlcipher-api/) — SQLCipher Community BSD-style; bundled copyright/license сохранён в `SQLCIPHER-LICENSE`. Apple CommonCrypto — системный provider, его наличие на macOS не доказывает cross-build iOS.
- [zeroize](https://docs.rs/zeroize/) — MIT OR Apache-2.0; ограничения исторических копий сохраняются.
- [SQLite transactions](https://www.sqlite.org/lang_transaction.html), [synchronous](https://www.sqlite.org/pragma.html#pragma_synchronous) — основания интерпретации транзакций и долговечности.

Условия App Store, экспортные требования и юридическая проверка всего продукта этим прототипом не выполнялись.
